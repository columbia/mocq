## Joern / PHP query harness (CPGQL, Scala)

The CPG for the target project is ALREADY loaded on the server. Do NOT call `importCode` / `importCpg`.
Write the query in exactly this shape. Do not deviate from the skeleton.

### Grammar sketch
```
<query>   ::= <defs> <find>
<defs>    ::= "def mocqSource = {" <trav> "}"
              "def mocqSink = {"   <trav> "}"
              [ "def mocqSanitizer = {" <trav> "}" ]
<find>    ::= "def findVulnerability() = " <flow> ".l"
<flow>    ::= "mocqSink.reachableByFlows(mocqSource)"
              [ ".filterNot(_.elements.exists(n => mocqSanitizer.contains(n)))" ]
<trav>    ::= "cpg" "." <nodeStep> ( "." <step> )*        // an Iterator[CfgNode]
<nodeStep>::= "call" | "identifier" | "literal" | "parameter" | "assignment" | "method" ...
<step>    ::= ".name(\"<re>\")" | ".code(\"<re>\")" | ".methodFullName(\"<re>\")"
            | ".where(_. <trav-pred> )" | ".filter(n => <bool> )" | ".filterNot(...)"
            | ".argument" | ".argument(<n>)" | ".receiver" | ".ast" | ".astChildren"
            | ".method" | ".caller" | ".callee" | ".file" | ".dedup"
```

- `mocqSource` / `mocqSink` MUST be top-level `def`s returning an Iterator of `CfgNode` (the
  orchestrator decomposes and scores the query through them). Put the real logic there.
- Keep them GENERAL: match on PHP superglobals, framework APIs, and call names — never on an identifier
  or string literal copied from a specific sample file.
- The query result must ultimately expose `.location` (file + line). End `findVulnerability` with `.l`.

### Curated step subset (use these; avoid the rest of the DSL)
Sources — user-controlled input
- superglobals: `cpg.call.name("<operator>.indexAccess").where(_.argument(1).code("(?i)\\$_(GET|POST|REQUEST|COOKIE|FILES)\\b"))`
- or the array itself: `cpg.identifier.name("_(GET|POST|REQUEST|COOKIE)")`
- request-reading calls: `cpg.call.name("(?i)file_get_contents|getenv|apache_request_headers|filter_input")`
- `RemoteFlowSource` is NOT available in Joern — model sources explicitly as above.

Sinks — dangerous operations
- SQLi: `cpg.call.name("(?i)mysqli?_query|mysqli_real_query|mysqli_multi_query|pg_query|sqlite_query|->?query|->?exec|->?prepare|query|exec")`
  then keep the argument that carries the query string: `.argument(1)` (procedural) or `.argument` (method)
- command injection: `cpg.call.name("(?i)system|exec|shell_exec|passthru|popen|proc_open|pcntl_exec")`
  plus backticks: `cpg.call.name("<operator>.backticks")`
- path traversal: `cpg.call.name("(?i)fopen|file_get_contents|file_put_contents|readfile|include|require|unlink|scandir")`
- XSS: `cpg.call.name("(?i)echo|print|printf|vprintf")` / assignments to `<operator>.assignment` whose
  target reaches an output

Sanitizers / barriers  (checked in `mocqSanitizer`, filtered out of flows manually)
- SQL: `cpg.call.name("(?i)mysqli?_real_escape_string|pg_escape_string|addslashes|->?quote|intval|(int)")`
  and parameterised queries (`->prepare` + `->bind_param` / `?` placeholders present)
- command: `cpg.call.name("(?i)escapeshellarg|escapeshellcmd")`
- path: `cpg.call.name("(?i)basename|realpath")` + a `str_replace("../")` / allow-list `in_array` check
- generic: `cpg.call.name("(?i)preg_match|ctype_[a-z]+|is_numeric|in_array")` guarding the value

Flow & helpers
- `sink.reachableBy(source)`  -> the source-reachable sink nodes (boolean reachability)
- `sink.reachableByFlows(source)`  -> `Iterator[Path]`; `path.elements` is the node list, each has
  `.code`, `.lineNumber`, `.file.name`
- `.location` -> `filename`, `lineNumber`; `.l` materialises; `.dedup` removes duplicates
- `cpg.method.name("foo")` to recover an unresolved call target by name
